# 选择困难症终结者 / DecisionMate

《移动智能应用开发》课程 Android 项目，2026 年秋季 Aberdeen 第 4 组。

仓库：[`2026-Autumn-Aberdeen-4-DecisionMate`](https://github.com/android-app-development-course/2026-Autumn-Aberdeen-4-DecisionMate)。

帮助用户解决“今天吃什么”“周末去哪里”“看哪部电影”等日常小决定，通过偏好反馈、多人协商和反向排除，给出更适合自己的选择。

## 项目状态

当前处于需求设计阶段。本仓库的初始内容为项目说明与开发计划，尚未包含可运行的 Android 应用。以下功能均为开发目标。

## 核心功能

### 1. 偏好学习

- 用户添加候选项，或从吃饭、出游、购物、电影等分类中选择。
- 每次推荐后，用户可选择“喜欢”“一般”“不喜欢”，并填写可选评价。
- 保存反馈历史，逐渐调整推荐权重，并显示简短的推荐原因。
- 第一版采用可解释的偏好评分；后续再接入 AI，理解自然语言评价与需求。

### 2. 多人决策

- 发起人创建房间，朋友在各自手机上通过房间码加入。
- 每个人提交候选项，标记“想选”“可以接受”“不接受”。
- 优先推荐所有人都可以接受、综合评分较高的选项。
- 没有共同可接受项时，提示补充选项或协商条件；平票时展示并列结果，由成员确认或随机选择。
- 跨手机实时同步需要后端服务，仅本地投票不算完成此功能。

### 3. 反向选择

- 用户输入“不想吃面、不想吃饭、不想吃辣”等排除条件。
- 第一版用结构化标签过滤候选项，后续用 AI 将自然语言转换为标签，并让用户确认。
- 排除条件优先于偏好评分，不推荐已被排除的选项。
- 候选项全部被排除时，明确显示原因，由用户决定是否修改条件。

## 第一版范围

先实现“今天吃什么”场景：添加候选项、选择排除标签、生成推荐、提交反馈、查看历史。

完整流程：候选项 -> 排除过滤 -> 偏好评分 -> 推荐结果 -> 用户反馈 -> 更新偏好。

## 开发计划

| 阶段 | 目标 | 验收方式 |
| --- | --- | --- |
| 1 | 创建仓库、确认需求和页面流程 | 项目说明完整，核心规则无歧义 |
| 2 | 建立 Android 工程，完成单人选择与排除 | 能在模拟器或手机完成一次选择，正确处理空候选与全部排除 |
| 3 | 保存反馈、偏好和历史 | 重启应用后仍可查看反馈，评分变化影响推荐 |
| 4 | 多人房间与投票同步 | 两台手机可加入同一房间、投票并看到一致结果 |
| 5 | AI 理解需求与评价 | 能解释推荐原因，AI 不可用时基础流程仍可运行 |
| 6 | 测试与课程演示 | 提供演示 APK、截图、测试记录和项目报告 |

## 初步页面

首页（选择场景）、候选项编辑、排除条件、推荐结果、反馈与历史、多人房间。

## 技术方案待确认

Android 开发语言、界面框架和最低支持版本应先与课程要求对齐。多人模式需要确定后端与登录方式；AI 模式需要确定模型服务、成本和数据处理方式。

AI 服务密钥放在服务端，不提交到仓库或打包进 APK。用户应能清除偏好与历史；联机上传的数据范围需在实现时明确。
